English is the working language of IT: documentation, error messages, forums, standards and many teams use it. The HTL English curriculum therefore covers not only everyday language but also the technical language of your own field. This includes technical vocabulary, describing processes and data, and the typical communication situations at work.

## Describing processes

To describe processes (how something works, how something is done), use:

-   the **present simple**, because the process is generally true
-   often the **passive**, because the system matters more than the person (see [Passive](/en/languages/english/passive_and_causative/#passive-in-technical-texts))
-   **sequence words**: `first`, `then`, `next`, `after that`, `once`, `as soon as`, `finally`
-   **cause and effect**: `causes`, `results in`, `leads to`, `as a result`, `so that`

> When you enter a URL, the browser first sends a request to a DNS server, which returns the IP address of the web server. Next, a TCP connection is established and the browser sends an HTTP request. The server then processes the request and sends back a response. Finally, the page is rendered by the browser.

## Describing graphs

### Types of graphs

| English           | Meaning                                     |
| ----------------- | ------------------------------------------- |
| line graph        | shows development over time                 |
| bar chart         | compares values with bars                   |
| pie chart         | shows proportions of a whole                |
| table             | data in rows and columns                    |
| flow chart        | shows the steps of a process                |
| x-axis, y-axis    | horizontal axis, vertical axis              |

### Describing trends

| Direction         | Verbs                                          | Nouns                                    |
| ----------------- | ---------------------------------------------- | ---------------------------------------- |
| upwards           | `rise`, `increase`, `grow`, `go up`, `climb`   | `a rise`, `an increase`, `growth`        |
| downwards         | `fall`, `decrease`, `decline`, `drop`, `go down` | `a fall`, `a decrease`, `a decline`, `a drop` |
| no change         | `remain stable`, `stay the same`, `level off`  | `a plateau`                              |
| up and down       | `fluctuate`                                    | `a fluctuation`                          |
| highest/lowest point | `peak at`, `reach a peak`, `hit a low`      | `a peak`, `a low point`                  |

| Degree            | Adjective (+ noun)        | Adverb (+ verb)             |
| ----------------- | ------------------------- | --------------------------- |
| strong, sudden    | `sharp`, `dramatic`, `steep`, `sudden` | `sharply`, `dramatically`, `steeply`, `suddenly` |
| clear             | `significant`, `considerable` | `significantly`, `considerably` |
| even              | `steady`, `gradual`       | `steadily`, `gradually`     |
| small             | `slight`, `small`         | `slightly`                  |

**Prepositions** are essential with figures:

-   `rose from 20% to 35%` (start and end value)
-   `rose by 15 percentage points` (difference)
-   `stood at 2 million` (value at a point in time)
-   `a rise of 10%` (noun + `of`)

> The line graph shows the number of registered users of our school app between 2020 and 2025. The number rose steadily from 400 to 1,150. The sharpest increase occurred between 2022 and 2023, when the app was introduced in all classes.

Note the English number format with a decimal point and a thousands comma.

## Technical documentation

Good technical documentation (instructions, README files, manuals) is written for readers who want to get something done. This leads to the following rules:

-   define the **target audience**: end users need different information from developers.
-   **instructions in the imperative**, one step per sentence, numbered: `1. Open the terminal. 2. Run the install script.`
-   **active voice and present simple**, short sentences, no filler words
-   **consistent terms**: once you say `folder`, do not suddenly switch to `directory`
-   mark notes and warnings clearly: `Note:`, `Warning:`, `Important:`
-   highlight controls and input, for example in bold: Click **Save**.

A typical structure of a README file:

| Section            | Content                                                     |
| ------------------ | ----------------------------------------------------------- |
| Project name       | name and one sentence on what the project does              |
| Features           | main functions                                              |
| Requirements       | prerequisites (operating system, runtime)                   |
| Installation       | installation steps                                          |
| Usage              | examples of use                                             |
| Configuration      | settings                                                    |
| Contributing       | how to contribute                                           |
| Licence            | licence                                                     |

| Phrases for instructions                      |
| --------------------------------------------- |
| To install ..., follow these steps:           |
| Make sure that ... before you ...             |
| If ... appears, click ...                     |
| This will ...                                 |
| Once ... has finished, ...                    |
| Note that ...                                 |

## Professional emails

At work, the tone is usually **neutral to formal**, but shorter and more direct than in a letter. You will find the layout and phrases under [Email](/en/languages/text_types/email/#formal-email). For everyday work, these phrases are also useful:

| Situation             | Phrases                                                                |
| --------------------- | ---------------------------------------------------------------------- |
| referring             | `Thank you for your email.` / `Following up on our call, ...`          |
| attachment            | `Please find attached ...` / `I have attached ...`                     |
| request               | `Could you please ...?` / `I would be grateful if you could ...`       |
| deadline              | `Could you send it by Friday?`                                         |
| reporting a problem   | `I'm writing to report a problem with ...` / `When I try to ..., the following error appears: ...` |
| following up          | `I'm just following up on my email from Monday.`                       |
| closing               | `Please let me know if you have any questions.` / `Best regards,`      |

:::tip[Bug report]
A good bug report contains: what you wanted to do, what you did (steps), what you expected (_expected behaviour_), what actually happened (_actual behaviour_), the error message and system information (version, operating system).
:::

## Meetings

| Situation                  | Phrases                                                                       |
| -------------------------- | ----------------------------------------------------------------------------- |
| opening                    | `Let's get started.` / `The purpose of today's meeting is to ...`             |
| agenda                     | `There are three items on the agenda.` / `Let's move on to the next point.`   |
| giving an opinion          | `In my view, ...` / `I think we should ...`                                   |
| agreeing                   | `I completely agree.` / `That's a good point.`                                |
| disagreeing (politely)     | `I see your point, but ...` / `I'm not sure I agree.` / `Have we considered ...?` |
| interrupting               | `Sorry to interrupt, but ...` / `Could I just add something?`                 |
| clarifying                 | `Could you clarify what you mean by ...?` / `So, if I understand you correctly, ...` |
| summarising                | `To sum up, we've agreed that ...`                                            |
| assigning tasks            | `Who will take care of ...?` / `Anna will ... by Friday.`                     |
| closing                    | `Is there anything else?` / `Thanks, everyone. Let's meet again next week.`   |

The results of a meeting are recorded in the _minutes_, with _action items_, the people responsible and deadlines.

## Phone calls and video conferences

| Situation                  | Phrases                                                                   |
| -------------------------- | ------------------------------------------------------------------------- |
| introducing yourself       | `Hello, this is Max Muster from Muster IT Solutions.` (not ~~I am Max~~ on the phone) |
| asking for someone         | `Could I speak to Ms Smith, please?`                                      |
| stating the reason         | `I'm calling about ...`                                                   |
| connecting                 | `Hold on, please. I'll put you through.`                                  |
| not available              | `I'm afraid she's not available at the moment. Can I take a message?`     |
| not understood             | `Sorry, could you repeat that?` / `Could you speak a bit more slowly?`    |
| spelling                   | `Could you spell that, please?`                                           |
| technical problems         | `You're breaking up.` / `I think you're on mute.` / `Can you see my screen?` |
| calling back               | `I'll get back to you by tomorrow.`                                       |
| ending                     | `Thanks for calling. Goodbye.`                                            |

### Saying email addresses and symbols

| Symbol  | Pronunciation                                |
| ------- | -------------------------------------------- |
| `@`     | at                                           |
| `.`     | dot                                          |
| `_`     | underscore                                   |
| `-`     | hyphen, dash                                 |
| `/`     | slash (`\` backslash)                        |
| `#`     | hash (BrE), pound sign (AmE)                 |
| `0`     | zero, in phone numbers often "oh" (BrE)      |

`max.muster@htl.at` is said "max dot muster at h-t-l dot a-t".

### Spelling alphabet

When spelling on the phone, people use the international **NATO phonetic alphabet**: Alfa, Bravo, Charlie, Delta, Echo, Foxtrot, Golf, Hotel, India, Juliett, Kilo, Lima, Mike, November, Oscar, Papa, Quebec, Romeo, Sierra, Tango, Uniform, Victor, Whiskey, X-ray, Yankee, Zulu. Example: `M as in Mike`.
