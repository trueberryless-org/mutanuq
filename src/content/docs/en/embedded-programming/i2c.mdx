**I²C** (_Inter-Integrated Circuit_, pronounced "I-squared-C") is a synchronous serial bus that Philips (today NXP) developed in 1982 for communication between chips on a circuit board. It needs only **two lines** for any number of devices: **SDA** (_Serial Data_) and **SCL** (_Serial Clock_). Typical I²C devices are temperature sensors, EEPROMs, real-time clocks (RTC), acceleration sensors, port expanders and small OLED displays.

Atmel calls the I²C interface of the AVR **TWI** (_Two-Wire Interface_) because the name I²C was trademarked. Technically, TWI is compatible with I²C.

:::note
Since revision 7 of the I²C specification (UM10204, 2021), NXP uses the terms **controller** and **target** instead of `master` and `slave`. The ATmega328P datasheet still uses the old terms.
:::

## Electrical design

All devices are connected in parallel to SDA and SCL. The outputs are **open drain** (or open collector): a device can only actively pull a line to 0 V, but cannot actively drive it high. The high level is provided by two **pull-up resistors**, typically $4.7\,\mathrm{k\Omega}$ to the supply voltage.

This results in a **wired AND**: the line is only high if not a single device pulls it low. A short circuit between two devices that output different levels at the same time is therefore impossible. Exactly this property makes clock stretching and arbitration between several controllers possible.

On the ATmega328P, SDA is on `PC4` and SCL on `PC5` (on the Arduino Uno they are also available as separate pins next to `AREF`).

### Sizing the pull-up resistors

The resistor must not be too small, because a device only has to sink $3\,\mathrm{mA}$ at the low level (at most $0.4\,\mathrm{V}$). It must not be too large either, because the bus capacitance $C_b$ forms an RC element together with $R_p$, and the rising edge has to finish within the permitted rise time $t_r$:

$$
R_{p,\min} = \frac{V_{DD} - 0.4\,\mathrm{V}}{3\,\mathrm{mA}} \qquad R_{p,\max} = \frac{t_r}{0.8473 \cdot C_b}
$$

**Example:** $V_{DD} = 5\,\mathrm{V}$, standard mode ($t_r = 1000\,\mathrm{ns}$), bus capacitance $C_b = 200\,\mathrm{pF}$:

$$
R_{p,\min} = \frac{4.6\,\mathrm{V}}{3\,\mathrm{mA}} \approx 1.53\,\mathrm{k\Omega} \qquad R_{p,\max} = \frac{1000\,\mathrm{ns}}{0.8473 \cdot 200\,\mathrm{pF}} \approx 5.9\,\mathrm{k\Omega}
$$

A $4.7\,\mathrm{k\Omega}$ resistor lies in between. In standard and fast mode, the total bus capacitance must not exceed $400\,\mathrm{pF}$, which is why I²C is only intended for short distances (a circuit board, a few decimetres of cable).

### Speeds

| Mode                   | Maximum bit rate   |
| ---------------------- | ------------------ |
| Standard mode (Sm)     | 100 kbit/s         |
| Fast mode (Fm)         | 400 kbit/s         |
| Fast mode plus (Fm+)   | 1 Mbit/s           |
| High speed mode (Hs)   | 3.4 Mbit/s         |
| Ultra fast mode (UFm)  | 5 Mbit/s (one direction only, without ACK) |

The ATmega328P supports standard and fast mode.

## Protocol

### Start and stop condition

While no transfer is running, both lines are high. During data transfer, SDA may only change while SCL is low. Two exceptions to this rule mark the beginning and end of a transfer:

- **Start** (S): SDA changes from high to low while SCL is high.
- **Stop** (P): SDA changes from low to high while SCL is high.
- **Repeated start** (Sr): another start condition without a preceding stop. This allows the controller to change direction (first write, then read) without releasing the bus.

The clock is always generated by the controller.

### Addressing

After the start, the controller sends a byte containing the **7-bit address** of the desired target and, as the eighth bit, the direction: **0 = write**, **1 = read**. This byte is called SLA+W or SLA+R. A target with the address `0x48` is therefore addressed with `0x90` for writing and `0x91` for reading.

7 bits allow 128 addresses, 16 of which are reserved (`0x00` to `0x07` and `0x78` to `0x7F`, for example for the general call and 10-bit addresses). The address is usually partly fixed by the manufacturer, and the lower bits can be set using address pins (`A0`, `A1`, `A2`). This allows up to eight identical devices on one bus. For larger systems there is also 10-bit addressing.

### Acknowledge

Each byte (8 bits) is followed by a ninth clock pulse for the **acknowledge**: the receiver pulls SDA low (**ACK**) and thereby confirms the byte. If SDA stays high, this is a **NACK**. A NACK after the address means that no target with this address responds. When reading, the controller deliberately sends a NACK after the last byte it wants, so that the target stops sending, followed by the stop condition.

### Sequence: reading a register

Most sensors have internal registers. To read a register, the controller first writes the register number (the **pointer**) and then reads:

| Step | Controller sends          | Target responds  |
| ---- | ------------------------- | ---------------- |
| 1    | Start                     |                  |
| 2    | Address + W               | ACK              |
| 3    | Register number           | ACK              |
| 4    | Repeated start            |                  |
| 5    | Address + R               | ACK              |
| 6    | ACK                       | Data byte 1      |
| 7    | NACK                      | Data byte 2      |
| 8    | Stop                      |                  |

### Clock stretching

A target that needs more time (for example because it first has to compute a measurement) may simply keep SCL low after the controller's low phase. When the controller releases SCL, it notices that the line does not go high and waits. This **clock stretching** is only possible because of the open-drain design. The AVR's TWI hardware takes it into account automatically.

### Arbitration

If two controllers start at the same time, both send their bits. A controller that sends a 1 (releases the line) but reads a 0 on SDA knows that another controller is sending. It has **lost arbitration** and backs off. The other controller notices nothing, and its transfer is not disturbed.

## TWI registers of the ATmega328P

| Register | Meaning |
| -------- | ------- |
| `TWBR`   | Bit rate register: sets the SCL frequency together with the prescaler |
| `TWSR`   | Status register: bits 7 to 3 contain the status code, bits 1 and 0 (`TWPS1`, `TWPS0`) the prescaler |
| `TWCR`   | Control register: controls the hardware (see below) |
| `TWDR`   | Data register: the byte to send or the byte received |
| `TWAR`   | Address register: own address when the AVR works as a target |

Important bits in `TWCR`:

| Bit     | Meaning |
| ------- | ------- |
| `TWINT` | Interrupt flag: set by the hardware when an action is finished. **Writing a 1** clears it and starts the next action. |
| `TWEA`  | Enable acknowledge: send ACK after receiving a byte |
| `TWSTA` | Generate start condition |
| `TWSTO` | Generate stop condition |
| `TWEN`  | Enable TWI |
| `TWIE`  | Enable TWI interrupt |

According to the datasheet, the SCL frequency is:

$$
f_{SCL} = \frac{f_{CPU}}{16 + 2 \cdot TWBR \cdot 4^{TWPS}}
$$

For $100\,\mathrm{kHz}$ at $16\,\mathrm{MHz}$ and prescaler 1 ($TWPS = 0$):

$$
TWBR = \frac{f_{CPU} / f_{SCL} - 16}{2} = \frac{160 - 16}{2} = 72
$$

After each action, the status register contains a code that you can use to check whether everything worked. The prescaler bits are masked out with `TWSR & 0xF8`:

| Code   | Meaning (controller mode) |
| ------ | ------------------------- |
| `0x08` | Start sent                |
| `0x10` | Repeated start sent       |
| `0x18` | SLA+W sent, ACK received  |
| `0x20` | SLA+W sent, NACK received |
| `0x28` | Data byte sent, ACK received |
| `0x30` | Data byte sent, NACK received |
| `0x40` | SLA+R sent, ACK received  |
| `0x48` | SLA+R sent, NACK received |
| `0x50` | Data byte received, ACK sent |
| `0x58` | Data byte received, NACK sent |

## Code

### Basic functions

```c
#define F_CPU 16000000UL

#include <avr/io.h>
#include <stdint.h>

void TWI_init(void) {
    TWSR = 0;              // prescaler 1
    TWBR = 72;             // 100 kHz at 16 MHz
    TWCR = (1<<TWEN);      // enable TWI
}

// Generate start or repeated start, returns the status code
uint8_t TWI_start(void) {
    TWCR = (1<<TWINT) | (1<<TWSTA) | (1<<TWEN);
    while (!(TWCR & (1<<TWINT)));
    return TWSR & 0xF8;
}

void TWI_stop(void) {
    TWCR = (1<<TWINT) | (1<<TWSTO) | (1<<TWEN);
    while (TWCR & (1<<TWSTO));   // wait until the stop has been sent
}

// Send one byte (address or data), returns the status code
uint8_t TWI_write(uint8_t data) {
    TWDR = data;
    TWCR = (1<<TWINT) | (1<<TWEN);
    while (!(TWCR & (1<<TWINT)));
    return TWSR & 0xF8;
}

// Receive one byte and acknowledge it with ACK (more bytes follow)
uint8_t TWI_read_ack(void) {
    TWCR = (1<<TWINT) | (1<<TWEN) | (1<<TWEA);
    while (!(TWCR & (1<<TWINT)));
    return TWDR;
}

// Receive the last byte and finish with NACK
uint8_t TWI_read_nack(void) {
    TWCR = (1<<TWINT) | (1<<TWEN);
    while (!(TWCR & (1<<TWINT)));
    return TWDR;
}
```

Setting `TWINT` with `TWCR = ...` looks confusing: writing a 1 **clears** the flag, and exactly that starts the next action of the hardware. When the action is finished, the hardware sets `TWINT` back to 1.

### Reading the LM75 temperature sensor

The **LM75** is a temperature sensor with the base address `0b1001xxx`. If the address pins `A2`, `A1`, `A0` are connected to GND, the address is `0x48`. The temperature register (pointer `0x00`) is 2 bytes long. On the LM75A, the upper 9 bits are used in two's complement with a resolution of $0.5\,\mathrm{°C}$, the remaining bits are 0.

```c
#define LM75_ADDR 0x48

// Returns the temperature in half degrees (e.g. 47 = 23.5 °C)
// or INT16_MIN on error
int16_t LM75_read_half_degrees(void) {
    if (TWI_start() != 0x08) { TWI_stop(); return INT16_MIN; }
    if (TWI_write(LM75_ADDR << 1) != 0x18) { TWI_stop(); return INT16_MIN; }  // SLA+W
    if (TWI_write(0x00) != 0x28) { TWI_stop(); return INT16_MIN; }            // pointer: temperature
    if (TWI_start() != 0x10) { TWI_stop(); return INT16_MIN; }                // repeated start
    if (TWI_write((LM75_ADDR << 1) | 1) != 0x40) { TWI_stop(); return INT16_MIN; } // SLA+R

    uint8_t msb = TWI_read_ack();
    uint8_t lsb = TWI_read_nack();
    TWI_stop();

    int16_t raw = (int16_t)(((uint16_t)msb << 8) | lsb);
    return raw / 128;   // upper 9 bits, 1 LSB = 0.5 °C
}
```

**Example:** The sensor returns `0x19` and `0x80`. Together that is `0x1980` = 6528, divided by 128 gives 51 half degrees, i.e. $25.5\,\mathrm{°C}$. For `0xFF80` (= -128 in two's complement) the result is -1, i.e. $-0.5\,\mathrm{°C}$.

### Writing and reading the 24C02 EEPROM

The **24C02** is an external EEPROM with 256 bytes (2 kbit). Its base address is `0b1010xxx`, so with `A2` to `A0` on GND it is `0x50`. The device address is followed by the memory address (one byte, 0 to 255). After a write, the device needs up to $5\,\mathrm{ms}$ for the internal write cycle and responds with NACK during this time. A **page write** can write up to 8 consecutive bytes of one page in a single cycle.

```c
#include <util/delay.h>

#define EEPROM_ADDR 0x50

uint8_t EEPROM_write_byte(uint8_t address, uint8_t value) {
    if (TWI_start() != 0x08) return 0;
    if (TWI_write(EEPROM_ADDR << 1) != 0x18) { TWI_stop(); return 0; }
    if (TWI_write(address) != 0x28) { TWI_stop(); return 0; }
    if (TWI_write(value) != 0x28) { TWI_stop(); return 0; }
    TWI_stop();
    _delay_ms(5);          // internal write cycle
    return 1;
}

uint8_t EEPROM_read_byte(uint8_t address) {
    TWI_start();
    TWI_write(EEPROM_ADDR << 1);        // write mode to set the address
    TWI_write(address);
    TWI_start();                        // repeated start
    TWI_write((EEPROM_ADDR << 1) | 1);  // read mode
    uint8_t value = TWI_read_nack();    // only one byte, therefore NACK
    TWI_stop();
    return value;
}
```

```c
int main(void) {
    TWI_init();
    EEPROM_write_byte(0x10, 42);
    uint8_t value = EEPROM_read_byte(0x10);   // 42
    int16_t t = LM75_read_half_degrees();     // e.g. 47 = 23.5 °C
    while (1) {
    }
}
```

Instead of the fixed waiting time you can also use **ACK polling**: the controller keeps sending start and SLA+W until the EEPROM responds with ACK again. This is faster because the actual write cycle is often shorter than $5\,\mathrm{ms}$. For the internal EEPROM of the ATmega328P see [EEPROM](/en/embedded-programming/eeprom/).

## Comparison with SPI and UART

| Property              | [UART](/en/embedded-programming/usart/) | I²C                          | [SPI](/en/embedded-programming/spi/) |
| --------------------- | ---------------------------------------- | ---------------------------- | ------------------------------------ |
| Lines                 | 2 (TX, RX) + GND                         | 2 (SDA, SCL) + GND           | 3 + 1 chip select per peripheral + GND |
| Clock                 | asynchronous (agreed baud rate)          | synchronous (SCL)            | synchronous (SCK)                    |
| Devices               | 2 (point to point)                       | many, via addresses          | many, via chip select lines          |
| Direction             | full duplex                              | half duplex                  | full duplex                          |
| Typical speed         | 9600 bit/s to about 1 Mbit/s             | 100 kbit/s to 1 Mbit/s       | several Mbit/s to over 50 Mbit/s     |
| Acknowledgement       | none (optional parity)                   | ACK after every byte         | none                                 |
| Several controllers   | no                                       | yes (arbitration)            | no                                   |
| Typical devices       | PC connection, GPS, Bluetooth modules    | sensors, RTC, EEPROM         | SD cards, displays, fast ADCs        |

I²C saves pins and wires but is slower than SPI and its protocol is more complex because of the addressing and the ACKs. SPI is faster and simpler but needs a separate chip select line for every device.
