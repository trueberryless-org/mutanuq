A **role** describes the tasks, authority and responsibility a person has in the project. Roles are not the same as people: one person can take on several roles, and one role can be shared by several people.

## Congruence principle

For every role, **tasks**, **authority** and **responsibility** must match. Anyone who is responsible for a result must also have the authority to make the decisions required for it. A project manager without budget authority, for example, cannot be held responsible for keeping to the costs.

## Client

The client (project sponsor) is usually a person from management or the business department that benefits from the project result.

- issues the project order and sets the objectives
- provides resources and budget
- supports the project manager and backs them up in conflicts with departments
- makes strategic decisions, for example about changes or cancelling the project
- accepts the project result and formally discharges the project manager

## Project manager

The project manager is responsible for achieving the project objectives.

- planning, steering and controlling the project
- leading and motivating the project team
- communicating with the client and stakeholders
- recognising and handling risks, conflicts and crises
- reporting, for example with status reports
- organising the project closing

Besides knowledge of methods, good project managers above all need social skills: the ability to communicate, assertiveness, the ability to handle conflict and the ability to lead a team without always being its line manager.

## Project team

The members of the project team work on the work packages.

- complete work packages on time and in the agreed quality
- report progress, problems and risks in good time
- take part in meetings and pass on information
- contribute expertise

Every work package has one responsible person who coordinates it, even if several people work on it.

## Responsibility assignment matrix

The **responsibility assignment matrix** shows clearly who has which function for which task. The rows contain the tasks or work packages, the columns contain the roles. A widespread form is the **RACI matrix**:

| Letter | Meaning         | Description                                                 |
| ------ | --------------- | ----------------------------------------------------------- |
| R      | Responsible     | carries out the task                                        |
| A      | Accountable     | has overall responsibility and decides, exactly one person per task |
| C      | Consulted       | is asked for expert advice beforehand                       |
| I      | Informed        | is informed about the result                                |

### Example

| Task                        | Client | Project manager | Development | IT operations | Business department |
| --------------------------- | ------ | --------------- | ----------- | ------------- | ------------------- |
| Write project order         | A      | R               | I           | I             | C                   |
| Gather requirements         | I      | A               | C           | C             | R                   |
| Develop software            |        | A               | R           | C             | C                   |
| Provide servers             |        | A               | C           | R             | I                   |
| Carry out acceptance        | A      | R               | I           | I             | C                   |

:::tip
Check every row: is there exactly one A? Is there at least one R? If a role has a lot of Rs, it is probably overloaded.
:::
