A function is **recursive** if it calls itself. Recursion is suitable for problems that can be broken down into smaller problems of the same kind: traversing directory trees, sorting with merge sort or computing mathematical sequences.

## Structure of a recursive function

Every recursive function needs two parts:

1. **Base case** (_termination condition_): for a smallest problem, the result is returned directly without another call.
2. **Recursive step**: the problem is reduced to a smaller problem of the same kind that gets closer to the base case.

The classic example is the factorial: $n! = n \cdot (n-1)!$ with the base case $0! = 1$.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(Factorial(5));   // 120
Console.WriteLine(SumDigits(4711)); // 13

static long Factorial(int n)
{
    if (n == 0) return 1;           // base case
    return n * Factorial(n - 1);    // recursive step
}

// digit sum: last digit + digit sum of the remaining digits
static int SumDigits(int n) => n < 10 ? n : n % 10 + SumDigits(n / 10);
```

</TabItem>
<TabItem label="Rust">

```rust
fn factorial(n: u64) -> u64 {

        return 1;                    // base case

    n * factorial(n - 1)             // recursive step
}

// digit sum: last digit + digit sum of the remaining digits
fn sum_digits(n: u32) -> u32 {
    if n < 10 { n } else { n % 10 + sum_digits(n / 10) }
}

fn main() {
    println!("{}", factorial(5));    // 120
    println!("{}", sum_digits(4711)); // 13
}
```

## The call stack

With every call, the program places a new **stack frame** containing the parameters and local variables on the [stack](/en/software-development/memory-management/#stack-and-heap). For `Factorial(3)`, this sequence is created:

```txt
Factorial(3)               waits for Factorial(2)
  Factorial(2)             waits for Factorial(1)
    Factorial(1)           waits for Factorial(0)
      Factorial(0) = 1     base case
    Factorial(1) = 1 · 1 = 1
  Factorial(2) = 2 · 1 = 2
Factorial(3) = 3 · 2 = 6
```

If the base case is missing or never reached, the function calls itself endlessly until the stack is full. The program then aborts with a **stack overflow**. Even with correct recursion, a very large recursion depth (tens of thousands of calls) can blow the stack.

### Recursion or iteration?

Every recursive function can also be written with a loop (iteratively), if necessary with a stack managed by yourself. Recursive code is often shorter and easier to understand for branching structures such as trees. Iterative code needs no stack memory per step and is usually a little faster.

If the recursive call is the **last operation** of the function (**tail recursion**), the compiler could turn it into a loop. Functional languages guarantee this. C# and Rust do not guarantee it, so for very deep recursion you should write a loop.

## Divide and conquer

With **divide and conquer**, a problem is broken down into several independent subproblems, which are solved recursively and whose solutions are then combined. Examples are [merge sort and quicksort](/en/software-development/algorithms/#merge-sort), binary search and fast exponentiation:

$$
x^n = \begin{cases} 1 & n = 0 \\ \left(x^{n/2}\right)^2 & n \text{ even} \\ x \cdot x^{n-1} & n \text{ odd} \end{cases}
$$

Instead of $n$ multiplications, this only needs $O(\log n)$.

### Towers of Hanoi

A tower of $n$ discs has to be moved from rod A to rod C. Only one disc may be moved at a time, and a larger disc must never lie on a smaller one. The recursive solution: move $n-1$ discs to B, the largest one to C and then the $n-1$ discs from B to C. This requires $2^n - 1$ moves.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(Power(2, 10));  // 1024
Hanoi(3, 'A', 'C', 'B');           // 7 moves

static long Power(long x, int n)
{
    if (n == 0) return 1;
    if (n % 2 == 0)
    {
        long half = Power(x, n / 2);
        return half * half;
    }
    return x * Power(x, n - 1);
}

static void Hanoi(int n, char from, char to, char via)
{
    if (n == 0) return;
    Hanoi(n - 1, from, via, to);
    Console.WriteLine($"Disc {n}: {from} -> {to}");
    Hanoi(n - 1, via, to, from);
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn power(x: u64, n: u32) -> u64 {
    if n == 0 {
        1
    } else if n % 2 == 0 {
        let half = power(x, n / 2);
        half * half
    } else {
        x * power(x, n - 1)
    }
}

fn hanoi(n: u32, from: char, to: char, via: char) {
    if n == 0 {
        return;
    }
    hanoi(n - 1, from, via, to);
    println!("Disc {n}: {from} -> {to}");
    hanoi(n - 1, via, to, from);
}

fn main() {
    println!("{}", power(2, 10)); // 1024
    hanoi(3, 'A', 'C', 'B');      // 7 moves
}
```

## Backtracking

**Backtracking** systematically tries all possibilities of building a solution step by step. If a partial path leads to a dead end, the last step is undone and the next possibility is tried. Typical applications are puzzles such as Sudoku, finding a way through a maze and enumerating all permutations or subsets.

A well-known example is the **n-queens problem**: in how many ways can $n$ queens be placed on an $n \times n$ chessboard so that none can capture another? You place one queen per row and check whether it shares a column or diagonal with a queen already placed. For the normal chessboard with $n = 8$, there are 92 solutions.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(CountQueens(8)); // 92

static int CountQueens(int n) => Place(new int[n], 0, n);

// columns[r] = column of the queen in row r
static int Place(int[] columns, int row, int n)
{
    if (row == n) return 1;                    // all queens placed: one solution
    int count = 0;
    for (int col = 0; col < n; col++)
    {
        if (IsSafe(columns, row, col))
        {
            columns[row] = col;                // try a step
            count += Place(columns, row + 1, n);
            // undoing is not necessary here because columns[row] is overwritten
        }
    }
    return count;
}

static bool IsSafe(int[] columns, int row, int col)
{
    for (int r = 0; r < row; r++)
    {
        int c = columns[r];
        if (c == col || Math.Abs(c - col) == row - r) return false; // column or diagonal
    }
    return true;
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn count_queens(n: usize) -> usize {
    let mut columns = vec![0; n];
    place(&mut columns, 0, n)
}

// columns[r] = column of the queen in row r
fn place(columns: &mut Vec<usize>, row: usize, n: usize) -> usize {
    if row == n {
        return 1; // all queens placed: one solution
    }
    let mut count = 0;
    for col in 0..n {
        if is_safe(columns, row, col) {
            columns[row] = col; // try a step
            count += place(columns, row + 1, n);
        }
    }
    count
}

fn is_safe(columns: &[usize], row: usize, col: usize) -> bool {
    (0..row).all(|r| {
        let c = columns[r];
        c != col && c.abs_diff(col) != row - r // column or diagonal
    })
}

fn main() {
    println!("{}", count_queens(8)); // 92
}
```

## Dynamic programming

With some recursive solutions, the same subproblems are computed again and again. The naive Fibonacci function $F(n) = F(n-1) + F(n-2)$, for example, calls itself about 2.7 million times for $F(30)$; its runtime grows exponentially. **Dynamic programming** stores the results of subproblems and reuses them. It requires that subproblems **overlap** and that the optimal solution is composed of optimal partial solutions.

- **Memoisation** (_top-down_): the recursive function stores every computed result in a table and looks there first.
- **Tabulation** (_bottom-up_): you fill a table iteratively, starting from the smallest subproblems.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
var memo = new Dictionary<int, long>();
Console.WriteLine(FibMemo(90, memo));   // 2880067194370816120
Console.WriteLine(FibTable(90));        // 2880067194370816120

// top-down with memoisation: O(n)
static long FibMemo(int n, Dictionary<int, long> memo)
{
    if (n < 2) return n;
    if (memo.TryGetValue(n, out long cached)) return cached;
    long result = FibMemo(n - 1, memo) + FibMemo(n - 2, memo);
    memo[n] = result;
    return result;
}

// bottom-up with a table: O(n)
static long FibTable(int n)
{
    if (n < 2) return n;
    var table = new long[n + 1];
    table[1] = 1;
    for (int i = 2; i <= n; i++)
    {
        table[i] = table[i - 1] + table[i - 2];
    }
    return table[n];
}
```

</TabItem>
<TabItem label="Rust">

```rust
use std::collections::HashMap;

// top-down with memoisation: O(n)
fn fib_memo(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {
    if n < 2 {
        return n;
    }
    if let Some(&cached) = memo.get(&n) {
        return cached;
    }
    let result = fib_memo(n - 1, memo) + fib_memo(n - 2, memo);
    memo.insert(n, result);
    result
}

// bottom-up with a table: O(n)
fn fib_table(n: usize) -> u64 {
    if n < 2 {
        return n as u64;
    }
    let mut table = vec![0u64; n + 1];
    table[1] = 1;
    for i in 2..=n {
        table[i] = table[i - 1] + table[i - 2];
    }
    table[n]
}

fn main() {
    println!("{}", fib_memo(90, &mut HashMap::new())); // 2880067194370816120
    println!("{}", fib_table(90));                     // 2880067194370816120
}
```

### Example: making change

With what smallest number of coins can an amount be paid? For every amount $b$: $\text{min}(b) = 1 + \min_{m} \text{min}(b - m)$ over all coin values $m \le b$. The table is filled from 0 up to the requested amount. The effort is $O(b \cdot k)$ for $k$ coin values.

## Greedy algorithms

A **greedy algorithm** makes the decision that looks best at the moment in every step and never takes it back. This is fast, but it only gives the optimal result for certain problems. For making change with euro coins, it works: you always take the largest coin that still fits. With the coin values 1, 3 and 4, however, the greedy strategy gives $4 + 1 + 1$ (three coins) for the amount 6, although $3 + 3$ (two coins) is better. Dynamic programming always finds the optimum.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
int[] coins = [1, 3, 4];
Console.WriteLine(GreedyCoins(coins, 6)); // 3 (4 + 1 + 1)
Console.WriteLine(MinCoins(coins, 6));    // 2 (3 + 3)

static int GreedyCoins(int[] coins, int amount)
{
    int count = 0;
    foreach (int coin in coins.OrderDescending())
    {
        count += amount / coin;
        amount %= coin;
    }
    return count;
}

static int MinCoins(int[] coins, int amount)
{
    var min = new int[amount + 1];
    Array.Fill(min, int.MaxValue);
    min[0] = 0;
    for (int b = 1; b <= amount; b++)
    {
        foreach (int coin in coins)
        {
            if (coin <= b && min[b - coin] != int.MaxValue)
                min[b] = Math.Min(min[b], min[b - coin] + 1);
        }
    }
    return min[amount];
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn greedy_coins(coins: &[u32], mut amount: u32) -> u32 {
    let mut sorted = coins.to_vec();
    sorted.sort_unstable_by(|a, b| b.cmp(a)); // descending
    let mut count = 0;
    for coin in sorted {
        count += amount / coin;
        amount %= coin;
    }
    count
}

fn min_coins(coins: &[usize], amount: usize) -> Option<usize> {
    let mut min = vec![usize::MAX; amount + 1];
    min[0] = 0;
    for b in 1..=amount {
        for &coin in coins {
            if coin <= b && min[b - coin] != usize::MAX {
                min[b] = min[b].min(min[b - coin] + 1);
            }
        }
    }
    (min[amount] != usize::MAX).then_some(min[amount])
}

fn main() {
    println!("{}", greedy_coins(&[1, 3, 4], 6));   // 3 (4 + 1 + 1)
    println!("{:?}", min_coins(&[1, 3, 4], 6));    // Some(2) (3 + 3)
}
```

Other well-known greedy algorithms are [Dijkstra's algorithm](/en/software-development/graphs/#dijkstras-algorithm) for shortest paths, the algorithms of Kruskal and Prim for minimum spanning trees and Huffman coding for [data compression](/en/computer-science/codes-and-compression/#huffman-coding).

## Overview

| Technique                    | Idea                                                                | Examples                                   |
| ---------------------------- | ------------------------------------------------------------------- | ------------------------------------------ |
| **Brute force**              | try all possibilities                                               | guessing passwords, linear search          |
| **Divide and conquer**       | split into independent subproblems, combine the solutions           | merge sort, quicksort, binary search       |
| **Backtracking**             | build a solution step by step, go back at dead ends                 | n-queens problem, Sudoku, maze             |
| **Dynamic programming**      | solve overlapping subproblems only once and store them              | Fibonacci, making change, knapsack problem, edit distance |
| **Greedy**                   | make the locally best choice in every step                          | Dijkstra, Kruskal, Huffman                 |
