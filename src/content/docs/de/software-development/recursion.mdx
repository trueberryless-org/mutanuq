Eine Funktion ist **rekursiv**, wenn sie sich selbst aufruft. Rekursion eignet sich für Probleme, die sich in kleinere Probleme derselben Art zerlegen lassen: das Durchlaufen von Verzeichnisbäumen, das Sortieren mit Mergesort oder das Berechnen mathematischer Folgen.

## Aufbau einer rekursiven Funktion

Jede rekursive Funktion braucht zwei Teile:

1. **Basisfall** (_Abbruchbedingung_): Für ein kleinstes Problem wird das Ergebnis direkt zurückgegeben, ohne weiteren Aufruf.
2. **Rekursionsschritt**: Das Problem wird auf ein kleineres Problem derselben Art zurückgeführt, das sich dem Basisfall nähert.

Das klassische Beispiel ist die Fakultät: $n! = n \cdot (n-1)!$ mit dem Basisfall $0! = 1$.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(Factorial(5));   // 120
Console.WriteLine(SumDigits(4711)); // 13

static long Factorial(int n)
{
    if (n == 0) return 1;           // Basisfall
    return n * Factorial(n - 1);    // Rekursionsschritt
}

// Quersumme: letzte Ziffer + Quersumme der restlichen Ziffern
static int SumDigits(int n) => n < 10 ? n : n % 10 + SumDigits(n / 10);
```

</TabItem>
<TabItem label="Rust">

```rust
fn factorial(n: u64) -> u64 {
    if n == 0 {
        return 1;                    // Basisfall
    }
    n * factorial(n - 1)             // Rekursionsschritt
}

// Quersumme: letzte Ziffer + Quersumme der restlichen Ziffern
fn sum_digits(n: u32) -> u32 {
    if n < 10 { n } else { n % 10 + sum_digits(n / 10) }
}

fn main() {
    println!("{}", factorial(5));    // 120
    println!("{}", sum_digits(4711)); // 13
}
```

## Der Aufrufstapel

Bei jedem Aufruf legt das Programm einen neuen **Stack Frame** mit den Parametern und lokalen Variablen auf den [Stack](/de/software-development/memory-management/#stack-und-heap). Für `Factorial(3)` entsteht diese Folge:

```txt
Factorial(3)               wartet auf Factorial(2)
  Factorial(2)             wartet auf Factorial(1)
    Factorial(1)           wartet auf Factorial(0)
      Factorial(0) = 1     Basisfall
    Factorial(1) = 1 · 1 = 1
  Factorial(2) = 2 · 1 = 2
Factorial(3) = 3 · 2 = 6
```

Fehlt der Basisfall oder wird er nie erreicht, ruft sich die Funktion endlos auf, bis der Stack voll ist. Das Programm bricht dann mit einem **Stack Overflow** ab. Auch bei korrekter Rekursion kann eine sehr große Rekursionstiefe (zehntausende Aufrufe) den Stack sprengen.

### Rekursion oder Iteration?

Jede rekursive Funktion lässt sich auch mit einer Schleife (iterativ) schreiben, notfalls mit einem selbst verwalteten Stack. Rekursiver Code ist bei verzweigten Strukturen wie Bäumen oft kürzer und verständlicher. Iterativer Code braucht keinen Stack-Speicher pro Schritt und ist meist etwas schneller.

Ist der rekursive Aufruf die **letzte Operation** der Funktion (**Endrekursion**, _tail recursion_), könnte der Compiler ihn in eine Schleife umwandeln. Funktionale Sprachen garantieren das. C# und Rust garantieren es nicht, daher sollte man für sehr tiefe Rekursionen eine Schleife schreiben.

## Teile und herrsche

Bei **Teile und herrsche** (_divide and conquer_) wird ein Problem in mehrere unabhängige Teilprobleme zerlegt, die rekursiv gelöst und deren Lösungen dann kombiniert werden. Beispiele sind [Mergesort und Quicksort](/de/software-development/algorithms/#mergesort), die binäre Suche und das schnelle Potenzieren:

$$
x^n = \begin{cases} 1 & n = 0 \\ \left(x^{n/2}\right)^2 & n \text{ gerade} \\ x \cdot x^{n-1} & n \text{ ungerade} \end{cases}
$$

Statt $n$ Multiplikationen braucht man so nur $O(\log n)$.

### Türme von Hanoi

Ein Turm aus $n$ Scheiben soll von Stab A nach Stab C verschoben werden. Es darf immer nur eine Scheibe bewegt werden, und nie darf eine größere auf einer kleineren liegen. Die rekursive Lösung: Verschiebe $n-1$ Scheiben nach B, die größte nach C und dann die $n-1$ Scheiben von B nach C. Dafür sind $2^n - 1$ Züge nötig.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(Power(2, 10));  // 1024
Hanoi(3, 'A', 'C', 'B');           // 7 Züge

static long Power(long x, int n)
{
    if (n == 0) return 1;
    if (n % 2 == 0)
    {
        long half = Power(x, n / 2);
        return half * half;
    }
    return x * Power(x, n - 1);
}

static void Hanoi(int n, char from, char to, char via)
{
    if (n == 0) return;
    Hanoi(n - 1, from, via, to);
    Console.WriteLine($"Scheibe {n}: {from} -> {to}");
    Hanoi(n - 1, via, to, from);
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn power(x: u64, n: u32) -> u64 {
    if n == 0 {
        1
    } else if n % 2 == 0 {
        let half = power(x, n / 2);
        half * half
    } else {
        x * power(x, n - 1)
    }
}

fn hanoi(n: u32, from: char, to: char, via: char) {
    if n == 0 {
        return;
    }
    hanoi(n - 1, from, via, to);
    println!("Scheibe {n}: {from} -> {to}");
    hanoi(n - 1, via, to, from);
}

fn main() {
    println!("{}", power(2, 10)); // 1024
    hanoi(3, 'A', 'C', 'B');      // 7 Züge
}
```

## Backtracking

**Backtracking** probiert systematisch alle Möglichkeiten aus, eine Lösung Schritt für Schritt aufzubauen. Führt ein Teilweg in eine Sackgasse, wird der letzte Schritt zurückgenommen und die nächste Möglichkeit versucht. Typische Anwendungen sind Rätsel wie Sudoku, das Finden eines Wegs durch ein Labyrinth und das Aufzählen aller Permutationen oder Teilmengen.

Ein bekanntes Beispiel ist das **Damenproblem**: Wie viele Möglichkeiten gibt es, $n$ Damen so auf ein $n \times n$-Schachbrett zu stellen, dass keine eine andere schlagen kann? Man setzt Zeile für Zeile eine Dame und prüft, ob sie mit einer bereits gesetzten in derselben Spalte oder Diagonale steht. Für das normale Schachbrett mit $n = 8$ gibt es 92 Lösungen.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
Console.WriteLine(CountQueens(8)); // 92

static int CountQueens(int n) => Place(new int[n], 0, n);

// columns[r] = Spalte der Dame in Zeile r
static int Place(int[] columns, int row, int n)
{
    if (row == n) return 1;                    // alle Damen gesetzt: eine Lösung
    int count = 0;
    for (int col = 0; col < n; col++)
    {
        if (IsSafe(columns, row, col))
        {
            columns[row] = col;                // Schritt ausprobieren
            count += Place(columns, row + 1, n);
            // Zurücknehmen ist hier nicht nötig, weil columns[row] überschrieben wird
        }
    }
    return count;
}

static bool IsSafe(int[] columns, int row, int col)
{
    for (int r = 0; r < row; r++)
    {
        int c = columns[r];
        if (c == col || Math.Abs(c - col) == row - r) return false; // Spalte oder Diagonale
    }
    return true;
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn count_queens(n: usize) -> usize {
    let mut columns = vec![0; n];
    place(&mut columns, 0, n)
}

// columns[r] = Spalte der Dame in Zeile r
fn place(columns: &mut Vec<usize>, row: usize, n: usize) -> usize {
    if row == n {
        return 1; // alle Damen gesetzt: eine Lösung
    }
    let mut count = 0;
    for col in 0..n {
        if is_safe(columns, row, col) {
            columns[row] = col; // Schritt ausprobieren
            count += place(columns, row + 1, n);
        }
    }
    count
}

fn is_safe(columns: &[usize], row: usize, col: usize) -> bool {
    (0..row).all(|r| {
        let c = columns[r];
        c != col && c.abs_diff(col) != row - r // Spalte oder Diagonale
    })
}

fn main() {
    println!("{}", count_queens(8)); // 92
}
```

## Dynamische Programmierung

Bei manchen rekursiven Lösungen werden dieselben Teilprobleme immer wieder berechnet. Die naive Fibonacci-Funktion $F(n) = F(n-1) + F(n-2)$ ruft sich für $F(30)$ zum Beispiel rund 2,7 Millionen Mal auf, ihre Laufzeit wächst exponentiell. **Dynamische Programmierung** speichert die Ergebnisse von Teilproblemen und verwendet sie wieder. Sie setzt voraus, dass sich Teilprobleme **überlappen** und sich die optimale Lösung aus optimalen Teillösungen zusammensetzt.

- **Memoisierung** (_top-down_): Die rekursive Funktion speichert jedes berechnete Ergebnis in einer Tabelle und schlägt dort zuerst nach.
- **Tabellierung** (_bottom-up_): Man füllt eine Tabelle iterativ von den kleinsten Teilproblemen aufwärts.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
var memo = new Dictionary<int, long>();
Console.WriteLine(FibMemo(90, memo));   // 2880067194370816120
Console.WriteLine(FibTable(90));        // 2880067194370816120

// top-down mit Memoisierung: O(n)
static long FibMemo(int n, Dictionary<int, long> memo)
{
    if (n < 2) return n;
    if (memo.TryGetValue(n, out long cached)) return cached;
    long result = FibMemo(n - 1, memo) + FibMemo(n - 2, memo);
    memo[n] = result;
    return result;
}

// bottom-up mit einer Tabelle: O(n)
static long FibTable(int n)
{
    if (n < 2) return n;
    var table = new long[n + 1];
    table[1] = 1;
    for (int i = 2; i <= n; i++)
    {
        table[i] = table[i - 1] + table[i - 2];
    }
    return table[n];
}
```

</TabItem>
<TabItem label="Rust">

```rust
use std::collections::HashMap;

// top-down mit Memoisierung: O(n)
fn fib_memo(n: u64, memo: &mut HashMap<u64, u64>) -> u64 {
    if n < 2 {
        return n;
    }
    if let Some(&cached) = memo.get(&n) {
        return cached;
    }
    let result = fib_memo(n - 1, memo) + fib_memo(n - 2, memo);
    memo.insert(n, result);
    result
}

// bottom-up mit einer Tabelle: O(n)
fn fib_table(n: usize) -> u64 {
    if n < 2 {
        return n as u64;
    }
    let mut table = vec![0u64; n + 1];
    table[1] = 1;
    for i in 2..=n {
        table[i] = table[i - 1] + table[i - 2];
    }
    table[n]
}

fn main() {
    println!("{}", fib_memo(90, &mut HashMap::new())); // 2880067194370816120
    println!("{}", fib_table(90));                     // 2880067194370816120
}
```

### Beispiel: Wechselgeld

Mit welcher kleinsten Anzahl Münzen lässt sich ein Betrag bezahlen? Für jeden Betrag $b$ gilt: $\text{min}(b) = 1 + \min_{m} \text{min}(b - m)$ über alle Münzwerte $m \le b$. Die Tabelle wird von 0 bis zum gesuchten Betrag gefüllt. Der Aufwand ist $O(b \cdot k)$ bei $k$ Münzwerten.

## Greedy-Algorithmen

Ein **gieriger Algorithmus** (_greedy_) trifft in jedem Schritt die Entscheidung, die im Moment am besten aussieht, und nimmt sie nie zurück. Das ist schnell, liefert aber nur bei bestimmten Problemen das optimale Ergebnis. Beim Wechselgeld mit Euro-Münzen funktioniert es: Man nimmt immer die größte Münze, die noch passt. Bei den Münzwerten 1, 3 und 4 liefert die Greedy-Strategie für den Betrag 6 aber $4 + 1 + 1$ (drei Münzen), obwohl $3 + 3$ (zwei Münzen) besser ist. Dynamische Programmierung findet immer das Optimum.

<Tabs syncKey="code">
<TabItem label="C#">

```csharp
int[] coins = [1, 3, 4];
Console.WriteLine(GreedyCoins(coins, 6)); // 3 (4 + 1 + 1)
Console.WriteLine(MinCoins(coins, 6));    // 2 (3 + 3)

static int GreedyCoins(int[] coins, int amount)
{
    int count = 0;
    foreach (int coin in coins.OrderDescending())
    {
        count += amount / coin;
        amount %= coin;
    }
    return count;
}

static int MinCoins(int[] coins, int amount)
{
    var min = new int[amount + 1];
    Array.Fill(min, int.MaxValue);
    min[0] = 0;
    for (int b = 1; b <= amount; b++)
    {
        foreach (int coin in coins)
        {
            if (coin <= b && min[b - coin] != int.MaxValue)
                min[b] = Math.Min(min[b], min[b - coin] + 1);
        }
    }
    return min[amount];
}
```

</TabItem>
<TabItem label="Rust">

```rust
fn greedy_coins(coins: &[u32], mut amount: u32) -> u32 {
    let mut sorted = coins.to_vec();
    sorted.sort_unstable_by(|a, b| b.cmp(a)); // absteigend
    let mut count = 0;
    for coin in sorted {
        count += amount / coin;
        amount %= coin;
    }
    count
}

fn min_coins(coins: &[usize], amount: usize) -> Option<usize> {
    let mut min = vec![usize::MAX; amount + 1];
    min[0] = 0;
    for b in 1..=amount {
        for &coin in coins {
            if coin <= b && min[b - coin] != usize::MAX {
                min[b] = min[b].min(min[b - coin] + 1);
            }
        }
    }
    (min[amount] != usize::MAX).then_some(min[amount])
}

fn main() {
    println!("{}", greedy_coins(&[1, 3, 4], 6));   // 3 (4 + 1 + 1)
    println!("{:?}", min_coins(&[1, 3, 4], 6));    // Some(2) (3 + 3)
}
```

## Überblick

| Technik                      | Idee                                                                | Beispiele                                  |
| ---------------------------- | ------------------------------------------------------------------- | ------------------------------------------ |
| **Brute Force**              | alle Möglichkeiten ausprobieren                                     | Passwort raten, lineare Suche              |
| **Teile und herrsche**       | in unabhängige Teilprobleme zerlegen, Lösungen kombinieren          | Mergesort, Quicksort, binäre Suche         |
| **Backtracking**             | Lösung schrittweise aufbauen, bei Sackgassen zurückgehen            | Damenproblem, Sudoku, Labyrinth            |
| **Dynamische Programmierung** | überlappende Teilprobleme nur einmal lösen und speichern           | Fibonacci, Wechselgeld, Rucksackproblem, Editierdistanz |
| **Greedy**                   | in jedem Schritt die lokal beste Wahl treffen                       | Dijkstra, Kruskal, Huffman                 |
