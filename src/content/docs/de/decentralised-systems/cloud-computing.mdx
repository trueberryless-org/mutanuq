Cloud Computing bezeichnet die Bereitstellung von IT-Ressourcen wie Rechenleistung, Speicher, Datenbanken oder ganze Anwendungen über das Internet, die bei Bedarf gemietet und nach tatsächlicher Nutzung abgerechnet werden. Große Cloud-Anbieter wie Google (Google Cloud), Microsoft (Azure) und Amazon (AWS) betreiben dafür riesige Rechenzentren auf der ganzen Welt und kümmern sich um Hardware, Wartung und eine hohe Verfügbarkeit. Programmierer können sich dadurch stärker auf die Applikationen und die Benutzerdaten konzentrieren. Diese Art, Software zu betreiben, ist in den letzten zwei Jahrzehnten immer beliebter geworden, da sie sowohl für die Anbieter als auch für die Kunden (Programmierer) einige Vorteile mit sich bringt.

## Übersicht

Je nachdem, wie viel der Anbieter übernimmt, unterscheidet man verschiedene Servicemodelle:

| Modell                                   | Der Anbieter verwaltet                                   | Der Kunde verwaltet                    | Beispiele                                    |
| ---------------------------------------- | -------------------------------------------------------- | -------------------------------------- | -------------------------------------------- |
| **IaaS** (Infrastructure as a Service)   | Hardware, Netzwerk, Virtualisierung                      | Betriebssystem, Laufzeit, Anwendung, Daten | Virtuelle Maschinen, virtuelle Netzwerke  |
| **PaaS** (Platform as a Service)         | zusätzlich Betriebssystem und Laufzeitumgebung           | Anwendung und Daten                    | Azure App Service, Azure Functions           |
| **SaaS** (Software as a Service)         | die gesamte Anwendung                                    | nur die eigenen Daten und Einstellungen | Microsoft 365, Gmail                        |

In diesem Kapitel beschäftigen wir uns großteils mit `PaaS` (Platform as a Service).

![IaaS, PaaS, SaaS](/images/decentralised_systems/iaas-paas-saas.png)

### Vorteile

-   flexibles Zahlen (nur das zahlen, was man verwendet)
-   einfache Skalierbarkeit (hinauf und hinunter)
-   niedriger Einstiegspreis
-   **hohe** Ausfallsicherheit (Service Level Agreement garantiert)

### Nachteile

-   bei dauerhaft hoher und gleichbleibender Last oft teurer als selber hosten
-   Abhängigkeit vom Anbieter (_Vendor Lock-in_), da viele Dienste nicht einfach zu einem anderen Anbieter umgezogen werden können
-   Datenschutz: Bei personenbezogenen Daten muss die DSGVO eingehalten werden, daher sollte man auf den Standort der Rechenzentren achten
-   Kosten können ohne Budgetgrenzen und Überwachung schnell unerwartet steigen

## Ressourcen / Services

Es gibt unterschiedliche Arten von Ressourcen, für welche man flexibel bezahlen muss:

### Rechenressourcen

Hierbei zahlt man für die Zeit, welche eine bestimmte Ressource läuft, und die Ausstattung und Hardware, welche diese Ressource besitzt.

| Beispiele                                                      |
| -------------------------------------------------------------- |
| App Service                                                    |
| Azure Function                                                 |
| Virtuelle Maschinen                                            |
| Container Registry (für die Verwaltung von Docker-Images)      |
| Container-Instanzen (für die Ausführung von Docker-Containern) |

### Speicherressourcen

Hierbei zahlt man für die Menge an Daten, welche man speichern möchte.

| Beispiele         |
| ----------------- |
| Storage account   |
| Azure Cosmos DB   |
| Data Lake Storage |

### Gemischte Ressourcen

Dies ist eine Mischung aus den obigen beiden Ressourcentypen. Bei einer Azure SQL Database zahlt man beispielsweise sowohl für die reservierte Rechenleistung als auch für den belegten Speicherplatz. Auch bei Azure Cosmos DB werden neben dem Speicher die verbrauchten Anfrageeinheiten (_Request Units_) verrechnet.

## Redundanz

Für viele Dienste kannst du den gewünschten Grad der Redundanz angeben. Dieser bestimmt, wie gut deine Daten gegen Hardwareausfälle, Naturkatastrophen und dergleichen geschützt sind und wiederhergestellt werden können.

### Lokal redundanter Speicher (LRS)

Hierbei werden deine Daten drei Mal innerhalb eines einzigen physischen Standortes (Rechenzentrums) in der primären Region gespeichert. Das ist die günstigste Variante, allerdings sind die Daten dadurch nicht sehr gut gegen Feuer, Überflutungen und sonstige Vernichtungsmöglichkeiten einzelner Standorte geschützt.

### Zonenredundanter Speicher (ZRS)

ZRS kopiert deine Daten synchron über drei Azure-Verfügbarkeitszonen in der primären Region. Verfügbarkeitszonen sind voneinander getrennte Rechenzentren mit eigener Strom-, Kühl- und Netzwerkversorgung. Deswegen wird dieser Grad der Redundanz für Anwendungen empfohlen, welche eine hohe Verfügbarkeit erfordern.

### Georedundanter Speicher (GRS)

Wie bei LRS werden die Daten drei Mal innerhalb eines einzigen physischen Standortes in der primären Region gespeichert. Zusätzlich werden sie asynchron in eine sekundäre Region kopiert, welche Hunderte von Kilometern von der primären Region entfernt ist. Dies sichert die Daten sehr gut gegen Naturkatastrophen. Die Haltbarkeit beträgt bei Azure mindestens `99,99999999999999%` (16 9er) pro Jahr.

### Geozonenredundanter Speicher (GZRS)

Die höchste Redundanz bietet GZRS, eine Kombination aus ZRS und GRS: In der primären Region werden die Daten über drei Verfügbarkeitszonen verteilt, zusätzlich wird eine Kopie in einer sekundären Region gespeichert. Bei den Varianten **RA-GRS** bzw. **RA-GZRS** (_Read Access_) kann man die Daten in der sekundären Region auch lesen, während die primäre Region ausgefallen ist.

## Skalierbarkeit

Für die meisten Services gibt es die Option, eine `Auto-Skalierung` einzustellen, damit bei vielen Anfragen mehrere Instanzen deiner Services gestartet werden können und bei Ruhezeiten diese automatisch wieder heruntergefahren werden können. Dabei handelt es sich um [horizontale Skalierung](/de/software-development/software-metrics/#horizontale-skalierung). Wechselt man hingegen auf einen leistungsstärkeren Tarif mit mehr CPU und Arbeitsspeicher, skaliert man vertikal.
