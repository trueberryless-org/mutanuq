**Cisco IOS** (_Internetwork Operating System_) ist das Betriebssystem der meisten Cisco-Router und -Switches. Im Unterricht und in der CCNA-Ausbildung wird es mit echten Geräten oder im Simulator **Cisco Packet Tracer** geübt. Die Befehle in diesem Kapitel gelten für IOS und IOS XE, andere Hersteller verwenden ähnliche Konzepte mit anderer Syntax. Die Grundlagen zu den einzelnen Funktionen stehen in den jeweiligen Kapiteln, hier geht es um die Konfiguration.

## Zugriff und CLI-Modi

Ein neues Gerät konfiguriert man über den **Konsolenport** (Rollover- oder USB-Kabel, Terminalprogramm mit 9600 Baud, 8 Datenbits, keine Parität, 1 Stoppbit). Später erfolgt der Zugriff per **SSH** über das Netz.

| Modus | Prompt | Erreichen mit | Zweck |
| --- | --- | --- | --- |
| **User EXEC** | `Router>` | Anmelden | eingeschränkte Anzeigebefehle |
| **Privileged EXEC** | `Router#` | `enable` | alle show-Befehle, Speichern, Neustart, debug |
| **Globale Konfiguration** | `Router(config)#` | `configure terminal` | Einstellungen für das ganze Gerät |
| **Interface-Konfiguration** | `Router(config-if)#` | `interface g0/0/0` | Einstellungen eines Interfaces |
| **Line-Konfiguration** | `Router(config-line)#` | `line console 0`, `line vty 0 15` | Konsolen- und Fernzugang |
| **Router-Konfiguration** | `Router(config-router)#` | `router ospf 10` | Routingprotokoll |

`exit` geht eine Ebene zurück, `end` oder Strg+Z direkt in den Privileged-EXEC-Modus. Befehle dürfen abgekürzt werden, solange sie eindeutig sind (`conf t`, `sh ip int br`). `?` zeigt mögliche Befehle und Parameter, die Tabulatortaste vervollständigt. `no` vor einem Befehl macht ihn rückgängig. Ein show-Befehl aus einem Konfigurationsmodus braucht ein vorangestelltes `do` (`do show ip interface brief`).

## Grundkonfiguration

```text
enable
configure terminal
hostname R1
no ip domain-lookup
enable secret Kl@ss3nPa55
service password-encryption
banner motd # Zugriff nur fuer autorisierte Personen #
line console 0
 password C0ns0le!
 login
 logging synchronous
 exec-timeout 5 0
 exit
```

- `hostname` setzt den Gerätenamen, Voraussetzung für SSH-Schlüssel.
- `no ip domain-lookup` verhindert, dass ein Tippfehler als Hostname interpretiert und per DNS gesucht wird (was die Konsole sekundenlang blockiert).
- `enable secret` schützt den Privileged-EXEC-Modus mit einem gehashten Passwort. Das ältere `enable password` speichert im Klartext und sollte nicht verwendet werden.
- `service password-encryption` verschleiert Klartextpasswörter in der Konfiguration (Typ 7). Das ist nur Schutz gegen Mitlesen über die Schulter, der Algorithmus ist trivial umkehrbar.
- `banner motd` zeigt beim Anmelden einen Hinweis an, juristisch wichtig, damit niemand behaupten kann, nicht gewarnt worden zu sein.
- `logging synchronous` verhindert, dass Statusmeldungen die Eingabe zerreißen, `exec-timeout 5 0` meldet nach 5 Minuten Inaktivität ab.

### SSH einrichten

```text
ip domain-name htl.example.at
username admin privilege 15 secret Adm1nPa55!
crypto key generate rsa general-keys modulus 2048
ip ssh version 2
line vty 0 15
 login local
 transport input ssh
 exit
```

1. Für den RSA-Schlüssel brauchen Hostname und Domänenname einen Wert, der Schlüssel heißt dann `R1.htl.example.at`.
2. `username ... secret` legt einen lokalen Benutzer an, `login local` verwendet die lokale Benutzerdatenbank.
3. `transport input ssh` erlaubt auf den virtuellen Terminals (VTY) nur SSH, kein Telnet.

Ein Switch braucht für den Fernzugriff eine IP-Adresse auf einem **SVI** und ein Default-Gateway, weil er selbst nicht routet:

```text
interface vlan 99
 ip address 192.168.99.11 255.255.255.0
 no shutdown
 exit
ip default-gateway 192.168.99.1
```

### Interfaces konfigurieren

```text
interface GigabitEthernet0/0/0
 description Link zu LAN Verwaltung
 ip address 192.168.10.1 255.255.255.0
 ipv6 address 2001:db8:acad:10::1/64
 ipv6 address fe80::1 link-local
 no shutdown
 exit
ipv6 unicast-routing
```

Router-Interfaces sind standardmäßig **administrativ abgeschaltet** und müssen mit `no shutdown` aktiviert werden, Switchports sind standardmäßig aktiv. `ipv6 unicast-routing` aktiviert IPv6-Routing und das Senden von Router Advertisements.

### Konfiguration speichern

Die laufende Konfiguration (**running-config**) liegt im RAM und geht bei einem Neustart verloren. Die Startkonfiguration (**startup-config**) liegt im NVRAM.

```text
copy running-config startup-config
```

Kurzform `copy run start` oder das ältere `write memory`. Mit `reload` startet das Gerät neu, mit `erase startup-config` und anschließendem `reload` wird es auf Werkseinstellungen gesetzt (bei Switches zusätzlich `delete vlan.dat`, damit auch die VLANs gelöscht werden). Konfigurationen sichert man mit `copy running-config tftp:` auf einen Server.

## show-Befehle

| Befehl | zeigt |
| --- | --- |
| `show running-config` | aktuelle Konfiguration |
| `show startup-config` | gespeicherte Konfiguration |
| `show version` | IOS-Version, Laufzeit, Hardware, Speicher, Konfigurationsregister |
| `show ip interface brief` | alle Interfaces mit IP-Adresse und Status (Status/Protokoll) |
| `show ipv6 interface brief` | dasselbe für IPv6 |
| `show interfaces g0/0/0` | Details: Geschwindigkeit, Duplex, Fehlerzähler (CRC, Collisions) |
| `show ip route` | Routingtabelle |
| `show arp` | ARP-Cache des Routers |
| `show mac address-table` | MAC-Tabelle eines Switches |
| `show vlan brief` | VLANs und zugeordnete Access-Ports |
| `show interfaces trunk` | Trunks, erlaubte VLANs, Native VLAN |
| `show spanning-tree` | Root Bridge, Portrollen und -zustände |
| `show etherchannel summary` | EtherChannel-Bündel und Mitglieder |
| `show ip ospf neighbor` | OSPF-Nachbarn und Zustand |
| `show ip protocols` | aktive Routingprotokolle, Router-ID, Netze |
| `show ip dhcp binding` | vergebene DHCP-Adressen |
| `show ip nat translations` | NAT-Tabelle |
| `show access-lists` | ACLs mit Trefferzählern |
| `show cdp neighbors detail` | direkt angeschlossene Cisco-Geräte mit IP und Modell |
| `show lldp neighbors` | direkt angeschlossene Geräte aller Hersteller |
| `show logging` | Logmeldungen |
| `show clock` | Uhrzeit (wichtig für Logs) |

Bei `show ip interface brief` bedeutet **up/up**, dass Schicht 1 und 2 funktionieren. **administratively down/down** heißt, das Interface ist mit `shutdown` abgeschaltet. **down/down** deutet auf ein Problem in Schicht 1 (kein Kabel, Gegenseite aus), **up/down** auf Schicht 2 (etwa falsche Kapselung).

Lange Ausgaben lassen sich filtern: `show running-config | include ip address`, `show running-config | section ospf`, `show ip route | begin Gateway`.

**CDP** (_Cisco Discovery Protocol_) und **LLDP** (_Link Layer Discovery Protocol_, IEEE 802.1AB) melden Nachbargeräten Name, Modell, Port und Adresse. Das ist praktisch für die Dokumentation, verrät aber auch Angreifern Details. Man schaltet es deshalb an Ports zu Endgeräten oder zum Internet ab (`no cdp enable` am Interface, `no cdp run` global).

## VLANs und Trunks

```text
vlan 10
 name Verwaltung
vlan 20
 name Schueler
vlan 99
 name Management
vlan 999
 name Unbenutzt
 exit

interface range FastEthernet0/1 - 12
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
 spanning-tree bpduguard enable
 exit

interface GigabitEthernet0/1
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,99
 switchport nonegotiate
 exit
```

- `switchport mode access` konfiguriert den Port fest als Access-Port, `switchport access vlan` ordnet ihn einem VLAN zu. Existiert das VLAN noch nicht, wird es automatisch angelegt.
- Ein Voice-VLAN für IP-Telefone kommt mit `switchport voice vlan 150` dazu.
- Auf älteren Switches mit ISL-Unterstützung braucht ein Trunk vorher `switchport trunk encapsulation dot1q`.
- Ungenutzte Ports schaltet man ab und legt sie in ein ungenutztes VLAN (`switchport access vlan 999`, `shutdown`).

### Inter-VLAN-Routing

Router-on-a-Stick mit Subinterfaces:

```text
interface GigabitEthernet0/0/1
 no shutdown
interface GigabitEthernet0/0/1.10
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
interface GigabitEthernet0/0/1.20
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
interface GigabitEthernet0/0/1.99
 encapsulation dot1Q 99 native
 ip address 192.168.99.1 255.255.255.0
```

Layer-3-Switch mit SVIs und einem gerouteten Port Richtung Router:

```text
ip routing
interface vlan 10
 ip address 192.168.10.1 255.255.255.0
 no shutdown
interface vlan 20
 ip address 192.168.20.1 255.255.255.0
 no shutdown
interface GigabitEthernet1/0/24
 no switchport
 ip address 10.0.0.2 255.255.255.252
```

Ein SVI ist nur **up**, wenn das VLAN existiert und mindestens ein Port in diesem VLAN aktiv ist (oder ein Trunk es überträgt).

### Spanning Tree und EtherChannel

```text
spanning-tree mode rapid-pvst
spanning-tree vlan 10,20 root primary
spanning-tree vlan 99 priority 4096

interface range GigabitEthernet0/1 - 2
 channel-group 1 mode active
 exit
interface port-channel 1
 switchport mode trunk
```

`root primary` setzt die Priorität so, dass der Switch Root Bridge wird (24576 oder niedriger als die aktuelle Root). `channel-group ... mode active` bündelt die Ports per LACP. Die Trunk-Einstellungen werden danach am logischen Interface `port-channel` gemacht.

### Port Security

```text
interface FastEthernet0/5
 switchport mode access
 switchport port-security
 switchport port-security maximum 2
 switchport port-security mac-address sticky
 switchport port-security violation restrict
```

Port Security begrenzt, wie viele MAC-Adressen ein Port lernen darf. `sticky` übernimmt die gelernten Adressen in die Konfiguration. Bei Verstößen gibt es drei Reaktionen: **shutdown** (Standard, Port geht in den Zustand err-disabled), **restrict** (fremde Frames verwerfen und protokollieren) und **protect** (nur verwerfen). Einen err-disabled-Port reaktiviert man mit `shutdown` und `no shutdown`.

## Statische Routen

```text
ip route 192.168.30.0 255.255.255.0 10.0.0.2
ip route 192.168.40.0 255.255.255.0 Serial0/1/0
ip route 0.0.0.0 0.0.0.0 203.0.113.1
ip route 0.0.0.0 0.0.0.0 198.51.100.1 5
ipv6 route 2001:db8:acad:30::/64 2001:db8:acad:ff::2
ipv6 route ::/0 GigabitEthernet0/0/0 fe80::2
```

Die vorletzte Zeile ist eine IPv6-Route über einen Next Hop, die letzte eine vollständig spezifizierte IPv6-Default-Route mit Link-Local-Next-Hop, bei der das Interface angegeben werden muss.

## OSPF

```text
interface loopback 0
 ip address 1.1.1.1 255.255.255.255
router ospf 10
 router-id 1.1.1.1
 network 192.168.10.0 0.0.0.255 area 0
 network 10.0.0.0 0.0.0.3 area 0
 passive-interface GigabitEthernet0/0/1
 auto-cost reference-bandwidth 10000
 default-information originate
```

- Die **Prozess-ID** (hier 10) ist nur lokal gültig und muss zwischen Nachbarn nicht übereinstimmen.
- `network` mit **Wildcard-Maske** aktiviert OSPF auf allen Interfaces, deren Adresse in diesem Bereich liegt. Alternativ aktiviert man OSPF direkt am Interface mit `ip ospf 10 area 0`.
- `passive-interface` verhindert Hellos auf Interfaces zu Endgeräten: Das Netz wird trotzdem bekannt gegeben, aber niemand kann dort eine Nachbarschaft aufbauen.
- `default-information originate` verteilt die eigene Default-Route an alle OSPF-Router.

Am Interface:

```text
interface GigabitEthernet0/0/0
 ip ospf priority 255
 ip ospf cost 50
 ip ospf hello-interval 5
 ip ospf dead-interval 20
 ip ospf network point-to-point
```

Prüfen mit `show ip ospf neighbor`, `show ip ospf interface brief`, `show ip route ospf` und `show ip protocols`.

## DHCP-Server auf dem Router

```text
ip dhcp excluded-address 192.168.10.1 192.168.10.20
ip dhcp pool VERWALTUNG
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.99.10
 domain-name htl.example.at
 lease 7
```

Die ausgeschlossenen Adressen sind für Gateway, Server und Drucker reserviert. Steht der DHCP-Server in einem anderen Netz, wird am Router-Interface der Clients ein Relay eingerichtet:

```text
interface GigabitEthernet0/0/1
 ip helper-address 192.168.99.10
```

Ein Router kann auch selbst per DHCP eine Adresse beziehen, etwa vom Provider: `ip address dhcp` am Interface.

## NAT

```text
interface GigabitEthernet0/0/1
 ip nat inside
interface GigabitEthernet0/0/0
 ip nat outside
 exit

access-list 1 permit 192.168.0.0 0.0.255.255
ip nat inside source list 1 interface GigabitEthernet0/0/0 overload

ip nat inside source static tcp 192.168.10.20 443 203.0.113.5 443
```

Die ACL wählt aus, welche inneren Adressen übersetzt werden, `overload` aktiviert PAT auf die Adresse des Outside-Interfaces. Die letzte Zeile ist eine Portweiterleitung. Statisches NAT ohne Ports lautet `ip nat inside source static 192.168.10.20 203.0.113.5`, dynamisches NAT verwendet einen Pool: `ip nat pool POOL 203.0.113.10 203.0.113.20 netmask 255.255.255.0` und `ip nat inside source list 1 pool POOL`. Kontrolle mit `show ip nat translations` und `show ip nat statistics`, Tabelle leeren mit `clear ip nat translation *`.

ACLs werden wie im Kapitel [NAT und ACLs](/de/networking/nat-and-acl/#beispiele) gezeigt konfiguriert und mit `ip access-group` angewendet.

## Netzwerkdienste

```text
ntp server 192.168.99.10
clock timezone CET 1
clock summer-time CEST recurring last Sun Mar 2:00 last Sun Oct 3:00
logging host 192.168.99.20
logging trap warnings
service timestamps log datetime msec
snmp-server community N0tPubl1c RO 5
```

Damit holt das Gerät die Zeit per NTP, protokolliert Meldungen bis zur Stufe 4 (warnings) an einen Syslog-Server und erlaubt SNMPv2c-Lesezugriff nur Adressen, die ACL 5 erlaubt. In Produktivnetzen verwendet man SNMPv3.

## Fehlersuche

| Befehl | Zweck |
| --- | --- |
| `ping 192.168.20.10` | Erreichbarkeit prüfen. `!` = Antwort, `.` = Timeout, `U` = Destination Unreachable. Der erste Ping schlägt oft fehl, weil erst ARP aufgelöst wird |
| `ping 192.168.20.10 source loopback 0` | erweiterter Ping mit anderer Quelladresse, prüft den Rückweg |
| `traceroute 192.168.20.10` | Weg Router für Router verfolgen |
| `show interfaces` | Fehlerzähler: steigende **CRC**-Fehler deuten auf Kabel oder Störungen, **Late Collisions** auf einen Duplex-Mismatch |
| `show ip interface brief` | ist das Interface up/up und hat es die richtige Adresse? |
| `show ip route` | gibt es eine Route zum Ziel und zurück? |
| `show cdp neighbors` | ist das richtige Gerät am richtigen Port angeschlossen? |
| `debug ip ospf adj` | Ereignisse live anzeigen, mit `undebug all` beenden. Vorsicht im Produktivbetrieb, debug kann die CPU auslasten |
| `terminal monitor` | Log- und Debug-Meldungen auch in einer SSH-Sitzung anzeigen |

Das allgemeine Vorgehen beschreibt [Fehlersuche im Netzwerk](/de/networking/network-troubleshooting/).
