Tasten sind eine Eingabe des Benutzers auf einfachster Hardware-Ebene. Die Taste kann entweder gedrückt sein oder eben nicht. Diese binäre Zustandsoption ermöglicht das einfache Konvertieren in „Spannung an“ oder „Spannung aus“.

## Theorie

Grundsätzlich gibt es zwei verschiedene Arten, Tasten zu verwenden:

- Active Low Beschaltung => Pull-Up Widerstand
- Active High Beschaltung => Pull-Down Widerstand

Diese beiden Arten müssen auf [Code-Ebene](#code) unterschiedlich verarbeitet werden.

### Active Low / Pull-Up

Bei der Active Low Beschaltung liegen **0V Spannung** (low) am Eingang an, wenn die Taste gedrückt ist (active). Der [Aufbau](#active-low--pull-up-1) einer Active Low Beschaltung verwendet den Pull-Up Widerstand.

### Active High / Pull-Down

Active High Beschaltungen funktionieren genau anders herum. Hierbei liegen die **5V Spannung** (high) am Eingang an, wenn die Taste gedrückt ist (active). Der [Aufbau](#active-high--pull-down-1) einer Active High Beschaltung verwendet den Pull-Down Widerstand.

## Aufbau

### Active Low / Pull-Up

Am korrespondierenden PIN baut man einen Spannungsteiler auf, welcher auf der einen Seite einen 10K Widerstand mit 5V Versorgungsspannung und auf der anderen Seite eine an den Ground angeschlossene Taste anliegen hat. Ist die Taste offen, „zieht“ der Widerstand den Pin auf 5V (high). Wird sie gedrückt, ist der Pin direkt mit GND verbunden (low).

_Ein Pull-Up Widerstand Aufbau, wenn die Taste geöffnet ist_

![Pull-Up Widerstand geschlossen](/images/embedded_programming/button/pull_up_widerstand_closed.png)
_Ein Pull-Up Widerstand Aufbau, wenn die Taste geschlossen ist_

### Active High / Pull-Down

Am korrespondierenden PIN liegt wieder ein Spannungsteiler an, welcher diesmal allerdings auf der Seite des 10K Widerstandes den Ground (GND) hat, und auf der anderen Seite befindet sich die Taste mit 5V Versorgungsspannung.

_Ein Pull-Down Widerstand Aufbau, wenn die Taste geöffnet ist_

_Ein Pull-Down Widerstand Aufbau, wenn die Taste geschlossen ist_

## Entprellen

Mechanische Tasten „prellen“: Beim Drücken und Loslassen schließen und öffnen die Kontakte einige Millisekunden lang mehrmals hintereinander, bevor sie einen stabilen Zustand erreichen. Der Mikrocontroller ist so schnell, dass er jeden dieser Wechsel als eigenen Tastendruck erkennen würde. In den folgenden Beispielen wird deshalb nach jeder Abfrage eine kurze Wartezeit (`_delay_ms(70)`) eingebaut. Alternativ kann man in Hardware einen Kondensator parallel zur Taste schalten.

## Code

### Ohne Interrupts

:::note
Achte genau auf die Unterschiede der if-Bedingungen!
:::

#### Pull-Up Beschaltung

```c
#include <avr/io.h>
#include <util/delay.h>

void checkButton(void);

int main(void)
{
    // Taste an Port B, Pin 0
    //  Port B, Pin 0 als Eingang konfigurieren
    DDRB &= ~(1<<DDB0);

    while (1)
    {
        checkButton();
    }
}

void checkButton(void) {
    // Überprüfen, ob die Taste gedrückt wird.
    if (!(PINB & (1<<PINB0)))
    {
        // Taste ist gedrückt
    }

    // Prellen vermeiden
    _delay_ms(70);
}
```

#### Pull-Down Beschaltung

```c
#include <avr/io.h>
#include <util/delay.h>

void checkButton(void);

int main(void)
{
    // Taste an Port B, Pin 0
    //  Port B, Pin 0 als Eingang konfigurieren
    DDRB &= ~(1<<DDB0);

    while (1)
    {
        checkButton();
    }
}

void checkButton(void) {
    // Überprüfen, ob die Taste gedrückt wird.
    if (PINB & (1<<PINB0))
    {
        // Taste ist gedrückt
    }

    // Prellen vermeiden
    _delay_ms(70);
}
```

#### Interner Pull-Up Widerstand

```c
#include <avr/io.h>
#include <util/delay.h>

void checkButton(void);

int main(void)
{
    // Taste an Port B, Pin 0
    //  Port B, Pin 0 als Eingang konfigurieren
    DDRB &= ~(1<<DDB0);

    //  Port B, Pin 0 Spannung: 5V (internen Pull-Up Widerstand aktivieren)
    PORTB |= (1<<PORTB0);

    while (1)
    {
        checkButton();
    }
}

void checkButton(void) {
    // Überprüfen, ob die Taste gedrückt wird.
    if (!(PINB & (1<<PINB0)))
    {
        // Taste ist gedrückt
    }

    // Prellen vermeiden
    _delay_ms(70);
}
```

Beim Polling ist die Bedingung so lange wahr, wie die Taste gedrückt gehalten wird. Soll eine Aktion nur **einmal pro Tastendruck** ausgeführt werden, merkt man sich den vorherigen Zustand und reagiert nur auf den Wechsel von „nicht gedrückt“ auf „gedrückt“ (_Flankenerkennung_):

```c
void checkButton(void) {
    static uint8_t wasPressed = 0;
    uint8_t isPressed = !(PINB & (1<<PINB0));

    if (isPressed && !wasPressed)
    {
        // Taste wurde soeben 1x gedrückt
    }

    wasPressed = isPressed;

    // Prellen vermeiden
    _delay_ms(70);
}
```

### Mit Interrupts

Mit Interrupts hat man den Vorteil, dass man nicht in der while-Schleife ständig eine Methode aufrufen muss, welche die Tasten abfragt. Dieses Verhalten wird bei den [Interrupts](/de/embedded-programming/interrupts) noch besser erklärt.

#### Direkte externe Interrupts

An Port D gibt es zwei PINs (2 und 3), welche über direkte externe Interrupt-Funktionalitäten (`INT0` und `INT1`) verfügen. Über das Register `EICRA` legt man fest, wann der Interrupt ausgelöst wird: bei einem low-Pegel (Standard), bei jeder Änderung, bei einer fallenden oder bei einer steigenden Flanke. Bei einer Pull-Up-Beschaltung erkennt man einen Tastendruck an der **fallenden Flanke**. Das bedeutet, dass dort angeschlossene Tasten spezifisch mithilfe von bereits definierten Interrupts überprüft werden können. Dies erspart ein wenig komplexen Programmcode.

```c
#include <avr/io.h>
#include <util/delay.h>
#include <avr/interrupt.h>

int main(void)
{
    // Taste an Port D, Pin 2
    //  Port D, Pin 2 als Eingang konfigurieren
    DDRD &= ~(1<<DDD2);

    //  Port D, Pin 2 Spannung: 5V (internen Pull-Up Widerstand aktivieren)
    PORTD |= (1<<PORTD2);

    // Interrupt
    //  bei fallender Flanke auslösen (ISC01 = 1, ISC00 = 0)
    EICRA |= (1<<ISC01);
    EICRA &= ~(1<<ISC00);
    //  direkten externen Interrupt an Port D, Pin 2 aktivieren
    EIMSK |= (1<<INT0);

    //  Set Enable Interrupt
    sei();

    while (1)
    {
    }
}

ISR (INT0_vect) {
    // Taste wurde 1x gedrückt

    _delay_ms(70);
}
```

:::caution
Ohne die Einstellung in `EICRA` wird der Interrupt auf den low-Pegel ausgelöst. Die ISR würde also ununterbrochen immer wieder aufgerufen, solange die Taste gedrückt ist. Außerdem sollten ISRs möglichst kurz sein. Ein `_delay_ms()` in der ISR blockiert währenddessen das gesamte Programm. In größeren Programmen setzt man in der ISR deshalb nur eine `volatile`-Variable und verarbeitet den Tastendruck in der Arbeitsschleife (siehe [Interrupts](/de/embedded-programming/interrupts/)).
:::

#### Gruppenbasierte externe Interrupts

Die gruppenbasierten externen Interrupts (_Pin Change Interrupts_) gelten immer für den gesamten Port und werden bei **jeder** Änderung ausgelöst, also sowohl beim Drücken als auch beim Loslassen. Aus diesem Grund muss man im Interrupt auch nochmals den richtigen PIN auf Tasteneingaben überprüfen, wie man unten im Code sehen kann. Mit `PCICR` aktiviert man den Interrupt für einen Port, mit `PCMSKx` wählt man die Pins aus, die ihn auslösen dürfen.

|       | Port B        | Port C         | Port D         |
| ----- | ------------- | -------------- | -------------- |
| PIN 0 | PCIE0, PCINT0 | PCIE1, PCINT8  | PCIE2, PCINT16 |
| PIN 1 | PCIE0, PCINT1 | PCIE1, PCINT9  | PCIE2, PCINT17 |
| PIN 2 | PCIE0, PCINT2 | PCIE1, PCINT10 | PCIE2, PCINT18 |
| PIN 3 | PCIE0, PCINT3 | PCIE1, PCINT11 | PCIE2, PCINT19 |
| PIN 4 | PCIE0, PCINT4 | PCIE1, PCINT12 | PCIE2, PCINT20 |
| PIN 5 | PCIE0, PCINT5 | PCIE1, PCINT13 | PCIE2, PCINT21 |
| PIN 6 | PCIE0, PCINT6 | PCIE1, PCINT14 | PCIE2, PCINT22 |
| PIN 7 | PCIE0, PCINT7 | -              | PCIE2, PCINT23 |

```c
#include <avr/io.h>
#include <util/delay.h>
#include <avr/interrupt.h>

int main(void)
{
    // Taste an Port D, Pin 4
    //  Port D, Pin 4 als Eingang konfigurieren
    DDRD &= ~(1<<DDD4);

    //  Port D, Pin 4 Spannung: 5V (internen Pull-Up Widerstand aktivieren)
    PORTD |= (1<<PORTD4);

    // Interrupt
    //  gruppenbasierten externen Interrupt an Port D, Pin 4 aktivieren
    PCICR |= (1<<PCIE2);
    PCMSK2 |= (1<<PCINT20);

    //  Set Enable Interrupt
    sei();

    while (1)
    {
    }
}

ISR (PCINT2_vect) {
    // notwendige Überprüfung des spezifischen PINs 4 auf Port D
    //  aufgrund der Verwendung von gruppenbasierten Interrupts
    if(!(PIND & (1<<PIND4))){
        // Taste wurde 1x gedrückt
    }

    _delay_ms(70);
}
```

## Troubleshooting

### Floating Input

Schließt man eine Taste nur zwischen 5V und dem Pin an, ohne einen Pull-Down-Widerstand zu verwenden, ist der Eingang bei offener Taste mit nichts verbunden. Er „schwebt“ (_floating_) und nimmt zufällige Werte an, etwa durch elektromagnetische Einstreuungen oder wenn man mit dem Finger in die Nähe kommt. Deshalb braucht jeder Eingang einen definierten Zustand über einen Pull-Up- oder Pull-Down-Widerstand:

![Floating Point](/images/embedded_programming/button/floating_point.png)

### Kurzschluss

Ebenso darf die Taste nicht ohne Widerstand gleichzeitig mit der Versorgungsspannung und dem Ground (GND) verbunden werden. Beim Drücken würde sonst ein Kurzschluss zwischen 5V und GND entstehen, der die Spannungsversorgung oder das Board beschädigen kann.

![Kurzschluss](/images/embedded_programming/button/kurzschluss.png)
