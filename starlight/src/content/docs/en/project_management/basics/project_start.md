The start of a project often decides whether it succeeds or fails. Mistakes made here, such as unclear objectives or a missing scope definition, can only be corrected later with great effort.

## Project order

The **project order** (also project charter) is the written agreement between the client and the project manager. When it is signed, the project officially begins. It makes clear what is to be achieved and gives the project manager the necessary authority.

A project order typically contains:

- project name and project number
- initial situation and reason for the project
- project objectives and non-objectives
- main tasks or project phases
- start and end date as well as important milestones
- budget and resources
- client, project manager and project team
- constraints and known risks
- date and signatures of client and project manager

### Example: project order for a diploma thesis

| Item                | Content                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| Project name        | "SmartRoom": room booking system for the school                                                      |
| Initial situation   | Rooms are booked via a spreadsheet, and double bookings are frequent.                                |
| Project objectives  | web application for booking all special rooms, sign-in with the school account, calendar overview   |
| Non-objectives      | booking of equipment, connection to the timetable software                                           |
| Start / end         | 15 September to 31 March                                                                             |
| Milestones          | functional specification approved, prototype finished, trial operation started, submission          |
| Resources           | 3 students with about 180 hours each, test server of the school                                      |
| Client              | school management, represented by the administrator                                                  |
| Project manager     | one person from the diploma thesis team                                                              |

## Requirements and functional specification

In projects with external clients, the requirements are often recorded in two documents:

- The **requirements specification** describes from the client's point of view what they need and why. It contains the business requirements and is written by the client.
- The **functional specification** describes from the contractor's point of view how and with what the requirements will be implemented. It is written by the contractor and approved by the client. After that, it is the binding basis for acceptance.

:::note
In agile projects, a continuously maintained product backlog often replaces the functional specification (see [process models](/en/project_management/basics/process_models/)).
:::

## Tasks at the project start

At the start of the project, the foundations for further work are laid:

1. define the project objectives and non-objectives precisely (see [project objectives](/en/project_management/basics/project_objectives/))
2. analyse the project context and the stakeholders (see [project context](/en/project_management/basics/project_context/))
3. define the project organisation and roles (see [project organisation](/en/project_management/organisation/))
4. create the first plans: work breakdown structure, schedule, resource and cost plan (see [project planning](/en/project_management/planning/))
5. identify and assess risks
6. agree on ground rules for cooperation, communication and documentation
7. document everything in the project handbook

## Kick-off meeting

The **kick-off meeting** (also start workshop) is the first meeting of everyone involved in the project. It has several goals:

- Everyone receives the same information about objectives, scope and plans.
- The team gets to know each other, and the roles are introduced.
- Ground rules for cooperation are agreed, such as meeting dates, communication channels and storage locations.
- The client shows that they stand behind the project, which increases motivation and acceptance.

A possible agenda:

1. welcome by the client, importance of the project
2. introduction of the team and the roles
3. project objectives, non-objectives and context
4. work breakdown structure, milestones and next steps
5. risks and open questions
6. ground rules and communication
7. agreement on the next meetings

:::tip
Also plan time for getting to know each other at the kick-off. A team whose members know each other raises problems earlier.
:::
